# Web Interaction & Tooling Conformance v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the desktop-first, map-first product interaction layer for Terraform and Roads while preserving the existing authoritative Terrain, Water, Road, save/load, and Undo architecture.

**Architecture:** Extend `terrain-core` with deterministic one-step support propagation and explicit core/support plan data; keep transient per-stamp Terraform acceptance in a focused Game application session; derive projected Water state without mutating Water; pass a semantic preview scene model to Three.js presentation; keep Road planning atomic for the whole command; and drive the HUD from immutable application presentation state. Production implementation remains on `agent/road-network-foundation-v0-1` / PR #11 and must not merge until all exact-head gates pass.

**Tech Stack:** TypeScript 6, Three.js 0.185.1, Vite 8, Vitest 4, Playwright 1.61.1, pnpm 10.13.1, Node.js >=22.

## Global Constraints

- Approved specification: `docs/superpowers/specs/2026-07-30-web-interaction-tooling-conformance-v0-1-design.md`.
- Approval record: `docs/superpowers/specs/2026-07-30-web-interaction-tooling-conformance-v0-1-approval.md`.
- Primary acceptance viewport is `1440 × 900` CSS pixels in Desktop Chromium with mouse and keyboard.
- Responsive compatibility smoke viewport is `390 × 844` CSS pixels; physical mobile-device acceptance is not a merge gate.
- Preserve `world-core → terrain-core/water-core/road-core → *-three → apps/game` dependency direction.
- `terrain-core` and `water-core` must not import Roads.
- Three.js packages must not own or mutate authoritative world state.
- Terraform values derive from one immutable pointer-down Terrain baseline.
- One unique Terrain vertex changes by at most one level per stroke.
- Flatten locks the initial Terrain-hit target and moves one level toward it per stroke.
- Terraform uses per-stamp acceptance inside one final release transaction.
- Roads retain atomic whole-command semantics.
- Automatic support propagation is bounded to four cell rings and 256 propagated vertices per tentative plan.
- Road-blocked Terraform must never enter authoritative Terrain mutation.
- Invalidity must not be communicated by color alone.
- Save formats remain unchanged.
- `pnpm-lock.yaml` must be generated by pnpm; manual integrity-bearing lockfile reconstruction is prohibited.
- Exact-head application build and WebGL acceptance are mandatory before merge.

- [ ] **Step 5: Implement the minimal bounded propagation algorithm**

Implement `propagateTerraformSupport` with this deterministic pipeline:

```text
validate snapshot and core cells
→ derive sorted unique core vertices
→ apply one operation step from baseline to core vertices
→ enqueue changed core vertices in Z-major/X-minor order
→ inspect N/E/S/W lattice neighbors
→ when a cardinal delta exceeds one, move only an operation-compatible unchanged neighbor one step from baseline
→ record support vertex and Chebyshev distance from the nearest core vertex
→ reject when distance exceeds four rings or support count exceeds 256
→ continue until queue drains
→ derive affected/support cells from incident cells of changed vertices
→ validate every affected cell plus one-cell halo with classifyTerrainShape
→ allow flat, cardinal ramps, and single-corner-high/low transitions
→ reject diagonal-ridge, diagonal-valley, saddle-or-twist, and severe-delta
```

Operation-compatible movement is exact:

```ts
function oneStepLevel(base: number, operation: TerraformOperation, target?: number): number {
  if (operation === 'raise') return base + 1;
  if (operation === 'lower') return base - 1;
  if (target === undefined) return Number.NaN;
  return base === target ? base : base + Math.sign(target - base);
}
```

A support vertex may move only in the same direction as the operation, or toward the locked Flatten target. Never clamp out-of-range values; return `terraform:height-range`.
